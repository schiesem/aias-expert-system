# SHACL Note Rules - Human Readable Format
# This file describes advisory rules that generate warnings/hints for the AI system design
# Each rule will be converted to SHACL syntax for validation

# IMPORTANT STRUCTURE NOTES (from AIAS-instance.owl):
# - Assignment is VDI3682:Assignment (not AIAS:Assignment)
# - ProcessOperator is VDI3682:ProcessOperator (not AIAS:ProcessOperator)
# - Functions (Inference, Training, etc.) are ISO22989 namespace
# - Components (EdgeDevice, CloudSystem, Sensor, etc.) are AIAS namespace
# - Property: AIAS:isAssignedTo connects both Functions and Components to Assignments
# - Pattern: Function →isAssignedTo→ Assignment ←isAssignedTo← Component

================================================================================
Rule 1: Inferenz auf externe Cloud - Latenzzeiten
================================================================================
WENN: Eine Instanz von ISO22989:Inference über VDI3682:Assignment mit AIAS:CloudSystem verbunden ist
      (beide nutzen AIAS:isAssignedTo zum selben Assignment)
DANN: Hinweis "Bei der Inferenz auf einer externen Cloud können hohe Latenzzeiten auftreten."
Betroffene Klassen: ISO22989:Inference, VDI3682:Assignment, AIAS:CloudSystem
Betroffene Properties: AIAS:isAssignedTo

REGULATION RULES (VORSCHRIFTEN UND RICHTLINIEN)
================================================================================

================================================================================
Rule I: AI-System Hochrisiko-Prüfung (EU AI Act Anhang III)
================================================================================
WENN: Ein AISystem existiert (Instanz von ISO22989:AISystem)
DANN: Hinweis "Es ist zu prüfen, ob das KI-System einer in Anhang III genannten Anwendungskategorie zugeordnet ist (z. B. sicherheitskritische Steuerung, Qualitätsfreigabe sicherheitsrelevanter Produkte, Zugangskontrolle) oder als sicherheitsrelevante Funktion einer regulierten Maschine / Anlage eingesetzt wird und damit als Hochrisiko-KI nach EU AI Act einzustufen ist."
Betroffene Klassen: ISO22989:AISystem
Betroffene Properties: Keine (nur Existenz prüfen)

================================================================================
Rule II: Entwicklungswerkzeuge Dokumentationspflicht (EU AI Act Anhang IV, 2a)
================================================================================
WENN: Trainings-, Validierungs-, Evaluations- oder Inferenz-Funktionen existieren
      (Instanzen von ISO22989:Training ODER ISO22989:Validation ODER ISO22989:Evaluation ODER ISO22989:Inference)
DANN: Hinweis "Wurden für die Entwicklung der KI weitere Werkzeuge eingesetzt? Wenn ja, ggf. die Pflicht zur Dokumentation der verwendeten Methoden und Werkzeuge nach Anhang IV, 2a beachten."
Betroffene Klassen: ISO22989:Training, ISO22989:Validation, ISO22989:Evaluation, ISO22989:Inference
Betroffene Properties: Keine (nur Existenz prüfen)

================================================================================
Rule III: Datenherkunft und -qualität Dokumentation (EU AI Act Art. 10)
================================================================================
WENN: Ein AISystem Training, Validation, Evaluation mit zugeordneten Datensätzen nutzt
      UND KEINE Acquisition (Herkunft) ODER DataProcess (Vorverarbeitung) im Modell existiert
DANN: Hinweis "Wenn Hochrisiko-KI sind Herkunft, Relevanz, Qualität und Eignung der Trainings- und Validierungsdaten zu dokumentieren nach EU AI Act, Art. 10"
Betroffene Klassen: ISO22989:AISystem, ISO22989:Training, ISO22989:Validation, ISO22989:Evaluation, ISO22989:Acquisition, ISO22989:DataProcess
Betroffene Properties: Kombination von Existenz- und Abwesenheitsprüfung
Hinweis: Komplexe Regel - erfordert Prüfung auf Existenz von Training/Validation/Evaluation UND Abwesenheit von Acquisition/DataProcess

================================================================================
Rule IV: Inferenz auf Prozess-Ressourcen - Menschliche Kontrolle (EU AI Act Art. 14)
================================================================================
WENN: Inference-Funktionen auf Ressourcen ausgeführt werden, die direkt in den technischen Prozess eingreifen
      (ISO22989:Inference über VDI3682:Assignment mit AIAS:Controller ODER AIAS:EdgeDevice ODER AIAS:Sensor ODER AIAS:Actuator verbunden ist
       UND diese Ressourcen mit VDI3682:ProcessOperator verbunden sind)
DANN: Hinweis "Prüfen, ob es sich aufgrund der Verteilung der Inferenzfunktionen um eine Regelungsaufgabe und ggf. um eine Hochrisikoanwendung handeln könnte. Wenn das der Fall ist, dann ist es wichtig, dass der Anwender eine erkennbare menschliche Kontroll- oder Abschaltmöglichkeit nach EU AI Act, Art 14 bereitstellt."
Betroffene Klassen: ISO22989:Inference, VDI3682:Assignment, VDI3682:ProcessOperator, AIAS:Controller, AIAS:EdgeDevice, AIAS:Sensor, AIAS:Actuator
Betroffene Properties: AIAS:isAssignedTo
Hinweis: Komplexe Regel - erfordert Prüfung ob Inference-Ressource auch mit ProcessOperator verbunden ist

================================================================================
Rule V: Cloud-Speicherung personenbezogener Daten (DSGVO Art. 6 Abs. 1)
================================================================================
WENN: Eine Instanz von ISO22989:Storage ODER ISO22989:DataProcess über VDI3682:Assignment mit AIAS:CloudSystem verbunden ist
DANN: Hinweis "Bei personenbezogenen Daten ist zu prüfen, ob eine Rechtsgrundlage nach Art. 6 Abs. 1 DSGVO vorliegt (z. B. Einwilligung, Vertrag, rechtliche Verpflichtung)."
Betroffene Klassen: ISO22989:Storage, ISO22989:DataProcess, VDI3682:Assignment, AIAS:CloudSystem
Betroffene Properties: AIAS:isAssignedTo

================================================================================

================================================================================
WENN: Eine Instanz von ISO22989:Storage ODER ISO22989:DataProcess über VDI3682:Assignment mit AIAS:CloudSystem verbunden ist

Betroffene Klassen: ISO22989:Storage, ISO22989:DataProcess, VDI3682:Assignment, AIAS:CloudSystem

IMPLEMENTATION STATUS:
================================================================================
✅ Rules 1-18, 29-31: Implemented in SHACL (shacl_rules_notes.ttl)
   - Assignment-based rules (Function to Component via Assignment)
   - Existence checks for specific function types

✅ Rules 19-27: Implemented in SPARQL (sparql_rules_notes.json)
   - Absence checks (checking for NON-existence of classes)
   - SHACL limitation: Cannot check for absence across entire ontology
   - Implementation: ASK queries with inverted logic

✅ Rule 28: Implemented in SPARQL (sparql_rules_notes.json)
   - Complex comparison (Training and Inference on different components)
   - SHACL limitation: Complex multi-way joins with component comparison
   - Implementation: SELECT query with FILTER for component inequality

✅ Rules I-VI: Implemented in SPARQL (sparql_rules_notes.json)
   - Regulation compliance checks (EU AI Act and GDPR)
   - Rule I: AISystem existence check (Hochrisiko-Prüfung)
   - Rule II: Development tools existence (OR logic for Training/Validation/Evaluation/Inference)
   - Rule III: Data documentation (complex existence AND absence check)
   - Rule IV: Inference on process resources (multi-level connection check)
   - Rule V: Cloud storage GDPR check (personal data)
   - Rule VI: Cloud storage consent check (company data)

VALIDATION WORKFLOW:
1. SHACL validation executes first (pyshacl with owlrl inference)
2. SPARQL validation executes second (SPARQLValidator module)
   - Absence checks (Rules 19-27)
   - Complex rules (Rule 28)
   - Regulation rules (Rules I-VI)
3. Results are combined and returned as unified notes list
